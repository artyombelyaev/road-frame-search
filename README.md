# Поиск кадров с дорог по тексту

По текстовому запросу вроде "night, rainy, highway" нужно найти подходящие кадры с видеорегистраторов BDD100K.
Релевантные кадры я определяю по разметке: у кадра есть погода, тип сцены и время суток, и он релевантен,
если совпадают все атрибуты запроса. Начинаю с CLIP без дообучения, дальше русские запросы и дообучение.

Результат: CLIP ViT-B/32 без дообучения на eval (val + test, 30 000 кадров, 86 запросов) даёт mAP 0,388
против 0,081 у случайной выдачи. Вариант промпта и обработки кадра я выбирал на train_sub (30 000 других кадров
из train), там у него mAP 0,384.

| | P@10 | P@50 | R-precision | mAP |
|---|---|---|---|---|
| CLIP, все 86 запросов | 0,686 | 0,621 | 0,420 | 0,388 |
| случайная выдача | 0,081 | 0,081 | 0,081 | 0,081 |
| CLIP, 14 запросов из 1 атрибута | 0,864 | 0,803 | 0,582 | 0,590 |
| CLIP, 39 запросов из 2 атрибутов | 0,723 | 0,649 | 0,428 | 0,398 |
| CLIP, 33 запроса из 3 атрибутов | 0,567 | 0,510 | 0,342 | 0,291 |

У случайной выдачи mAP для запросов из 1, 2 и 3 атрибутов 0,215, 0,077 и 0,030: чем больше атрибутов,
тем меньше релевантных кадров. Хуже всего CLIP находит partly cloudy (mAP 0,170 по 11 запросам) и dawn/dusk (0,195 по 19),
foggy есть только в одном запросе (0,109). Лучше всего - день и ночь (0,476 и 0,490). Разбивка по значениям - `results/zs_eval_by_value.csv`,
по запросам - `results/zs_eval_per_query.csv`.

## Как устроено решение

1. Данные. Взял кадры из `bdd100k_images_100k.zip` (70 000 train, 10 000 val, 20 000 test) и разметку из
   `bdd100k_labels.zip`, в котором свой JSON на каждый кадр. В нём размечен и test: у всех 20 000 кадров есть
   атрибуты и рамки объектов, в среднем 18,4 рамки на кадр, как в train. В каждом сплите JSON столько же,
   сколько картинок, имена совпадают, у каждого JSON есть все три атрибута (`results/labels_check.csv`).
   Поэтому для финальных метрик объединил val и test (eval, 30 000 кадров): так больше редких запросов проходит
   порог. Всё, что подбираю, подбираю на случайных 30 000 кадрах из train (train_sub), остальные 40 000 train
   оставил на дообучение. По эмбеддингам нашлось 4 пары почти одинаковых кадров, одна из них - между test
   и train_sub. Это один кадр из 30 000 в eval, я его оставил.
2. undefined. Погода не определена у 12% кадров, и это не случайные кадры: у 88% туннелей погоды нет, в туннеле её
   не видно. Если выкинуть все кадры с undefined, от туннелей в eval останется 8 из 76. Поэтому галерея своя
   у каждого запроса: выкидываю только кадры с undefined в атрибутах этого запроса.
3. Запросы. Перебрал все сочетания из 1, 2 и 3 атрибутов, их 195. У 39 в eval нет ни одного релевантного кадра
   (например, snowy + tunnel). Оставил запросы, у которых релевантных не меньше 50 и в eval, и в train_sub:
   на таком пороге P@50 может дойти до 1 у каждого запроса. Осталось 86 запросов: 14 из одного атрибута,
   39 из двух, 33 из трёх. Из одиночных отпал только gas stations, в eval у него 13 кадров. Сколько запросов
   остаётся на других порогах - в `results/threshold_counts.csv`.
4. Метрики. Релевантных на запрос от 51 до 18 400, доля в галерее от 0,2% до 62%. Считаю P@10 и P@50
   (первый экран), R-precision и AP по всей выдаче (если нужно вытащить все такие кадры, например для разметки).
   У случайной выдачи P@k и AP примерно равны доле релевантных, поэтому рядом с каждой метрикой пишу её значение
   для случайной выдачи, для AP - по точной формуле. Средние даю по всем запросам, по числу атрибутов
   и по каждому значению атрибута.
5. Эмбеддинги. CLIP ViT-B/32 для всех 100 000 кадров считаю один раз в Colab на T4 и храню нормированными
   во float16. Перед полным проходом сверил 256 кадров, посчитанных в Colab на GPU, с теми же кадрами на CPU:
   минимальный косинус 0,99998 для центра кадра и 0,99996 для кадра с полями.
6. Варианты. На train_sub сравнил 12 вариантов:
   - обработка кадра: стандартный центр CLIP (по бокам теряется 44% ширины кадра 16:9) или весь кадр с полями;
   - шаблон: сырые метки через запятую, фраза "a photo of a highway in the rain at night" или та же фраза
     про видеорегистратор;
   - скоринг: косинус с эмбеддингом всего запроса или CLIP как классификатор по каждому атрибуту запроса
     с суммой log-вероятностей.

   Выиграл центр кадра, фраза и скоринг по атрибутам. Разницу с другими вариантами проверил парным бутстрэпом
   по запросам (10 000 повторов, `results/zs_train_sub_bootstrap.csv`):
   - Скоринг по атрибутам дал больше всего: косинус со всем запросом хуже на 0,090 mAP (95% интервал
     от 0,073 до 0,108). Он лучше и на запросах из одного атрибута: 0,580 против 0,486 в среднем по шести
     вариантам с каждым скорингом. Значит, дело не только в том, что CLIP плохо склеивает условия: сравнение
     кадра со всеми значениями атрибута (softmax) помогает и само по себе.
   - Фраза лучше сырых меток на 0,042 (от 0,026 до 0,058). На запросах из одного атрибута метки не хуже:
     mAP 0,547 против 0,544 в среднем по четырём вариантам с каждым шаблоном.
   - Весь кадр с полями хуже центра на 0,009 (от 0,002 до 0,015), хотя P@10 у него выше: 0,677 против 0,655.
   - Префикс про видеорегистратор не помог. Второе место отличается от первого только им, разница 0,006,
     интервал от -0,002 до 0,014 накрывает ноль. Эти два варианта не различаются, первый я взял по правилу.

   Бутстрэп считает запросы независимыми, а у них общие кадры и атрибуты, поэтому интервалы скорее узкие.
7. Ошибки. В топ-50 запросов из 2 и 3 атрибутов чаще всего не совпадает погода (26-29% кадров), реже сцена (20%)
   и время суток (13-14%). Метки погоды и сами шумные: ночью 82% кадров размечены как clear, потому что облаков
   не видно, а snowy - чаще снег на обочине, чем снегопад. Лучший вариант я посчитал на eval один раз, после этого
   ничего не менял.

## Как запустить

Нужен Python 3.13.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

`bdd100k_images_100k.zip` и `bdd100k_labels.zip` с bdd-data.berkeley.edu положите в `data/` (или укажите папку
в переменной `BDD_DATA_DIR`). Распаковывать их не нужно.

1. Таблица кадров и запросы, около минуты:
   ```bash
   .venv/bin/python -m src.data
   .venv/bin/python -m src.queries
   ```
2. Эталон для сверки, около минуты на CPU:
   ```bash
   .venv/bin/python -m src.embed --mode crop --limit 256 --device cpu --out artifacts/check_cpu
   .venv/bin/python -m src.embed --mode pad --limit 256 --device cpu --out artifacts/check_cpu
   ```
3. Эмбеддинги в Colab на T4. Положите в `MyDrive/bdd100k/` архив `bdd100k_images_100k.zip` и папку
   `artifacts/check_cpu` (как `check_cpu/`), запустите `notebooks/02_colab_embeddings.ipynb`. Проход по 100 000
   кадров в одном варианте занял у меня 47 минут (pad, по времени файлов на Drive). Если сессия оборвётся,
   запустите ноутбук заново: готовые куски по 10 000 кадров пропустятся. Архив с Drive ноутбук копирует
   с докачкой: большие файлы Drive отдаёт с обрывами. Скачайте из `MyDrive/bdd100k/emb/` файлы `clip_b32_*`
   в `artifacts/emb/`.
4. Выбор варианта на train_sub и метрики на eval, меньше минуты:
   ```bash
   .venv/bin/python -m src.evaluate --part train_sub
   .venv/bin/python -m src.evaluate --part eval
   ```
   Вторая команда считает только вариант из `results/zs_choice.json`, который записала первая.

Тесты: `.venv/bin/python -m pytest -q`.

## Структура

- `src/config.py` - пути и константы.
- `src/data.py` - таблица кадров из архива разметки, сверка с архивом картинок, части train_sub / eval / train.
- `src/queries.py` - запросы из сочетаний атрибутов, галерея запроса, порог.
- `src/prompts.py` - тексты запросов по шаблонам.
- `src/embed.py` - эмбеддинги CLIP для кадров (crop и pad) кусками с докачкой, тексты, сверка двух прогонов.
- `src/metrics.py` - P@k, R-precision, AP и их ожидание для случайной выдачи.
- `src/evaluate.py` - скоринг, метрики по запросам, разбивки, выбор варианта на train_sub и бутстрэп.
- `notebooks/01_eda.ipynb` - разметка, undefined, сочетания атрибутов, выбор порога.
- `notebooks/02_colab_embeddings.ipynb` - эмбеддинги кадров в Colab.
- `notebooks/03_zero_shot.ipynb` - сравнение вариантов, метрики на eval, удачные и провальные запросы.
- `tests/` - тесты метрик, запросов, эмбеддингов и оценки на игрушечных примерах.
- `results/` - таблицы и графики, на которые ссылается README.
