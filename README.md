# Поиск кадров с дорог по тексту

По текстовому запросу вроде "night, rainy, highway" нужно найти подходящие кадры с видеорегистраторов BDD100K.
Релевантные кадры я определяю по разметке: у кадра есть погода, тип сцены и время суток, и он релевантен,
если совпадают все атрибуты запроса. Начинаю с CLIP без дообучения, дальше русские запросы и дообучение.

Результатов пока нет: эмбеддинги кадров считаются в Colab.

## Как устроено решение

1. Данные. Взял разметку и кадры BDD100K: 70 000 train, 10 000 val, 20 000 test. У test в моём архиве разметка тоже
   есть, поэтому для финальных метрик объединил val и test (eval, 30 000 кадров): так больше редких запросов проходит
   порог. Всё, что подбираю, подбираю на случайных 30 000 кадрах из train (train_sub), остальные 40 000 train
   оставил на дообучение.
2. undefined. Погода не определена у 12% кадров, и это не случайные кадры: у 88% туннелей погоды нет, в туннеле её не
   видно. Если выкинуть все кадры с undefined, от туннелей в eval останется 8 из 76. Поэтому галерея своя у каждого
   запроса: выкидываю только кадры с undefined в атрибутах этого запроса.
3. Запросы. Перебрал все сочетания из 1, 2 и 3 атрибутов, их 195. У 39 в eval нет ни одного релевантного кадра
   (например, snowy + tunnel). Оставил запросы, у которых релевантных не меньше 50 и в eval, и в train_sub:
   на таком пороге P@50 может дойти до 1, а дальше кривая числа запросов почти не меняется. Осталось 86 запросов:
   14 из одного атрибута, 39 из двух, 33 из трёх. Из одиночных отпал только gas stations, в eval у него 13 кадров.
4. Метрики. Релевантных на запрос от 51 до 18 400, доля в галерее от 0,2% до 62%. Считаю P@10 и P@50 (первый экран),
   R-precision и AP по всей выдаче (если нужно вытащить все такие кадры, например для разметки). У случайной выдачи
   P@k и AP примерно равны доле релевантных, поэтому рядом с каждой метрикой пишу её значение для случайной выдачи,
   для AP - по точной формуле. Средние даю по всем запросам, по числу атрибутов и по каждому значению атрибута.
5. Zero-shot CLIP. Эмбеддинги ViT-B/32 для всех кадров считаю один раз в Colab. На train_sub сравниваю 12 вариантов:
   - обработка кадра: стандартный центр CLIP (по бокам теряется 44% ширины кадра 16:9) или весь кадр с полями;
   - шаблон: сырые метки через запятую, фраза "a photo of a highway in the rain at night" или та же фраза
     про видеорегистратор;
   - скоринг: косинус с эмбеддингом всего запроса или CLIP как классификатор по каждому атрибуту запроса
     с суммой log-вероятностей.

   Лучший по mAP на train_sub считаю на eval один раз. Для запросов из 2 и 3 атрибутов смотрю, какой атрибут
   чаще всего не совпадает в топ-50.

## Как запустить

Нужен Python 3.13.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

`bdd100k_images_100k.zip` и `bdd100k_labels.zip` с bdd-data.berkeley.edu положите в `data/` (или укажите папку
в переменной `BDD_DATA_DIR`). Распаковывать их не нужно.

1. Таблица кадров и запросы, около минуты:
   ```bash
   .venv/bin/python -m src.data
   .venv/bin/python -m src.queries
   ```
2. Эмбеддинги в Colab на T4. Положите `bdd100k_images_100k.zip` в `MyDrive/bdd100k/` и запустите
   `notebooks/02_colab_embeddings.ipynb`. Скачайте `MyDrive/bdd100k/emb/` в `artifacts/emb/`.
3. Выбор варианта на train_sub и метрики на eval:
   ```bash
   .venv/bin/python -m src.evaluate --part train_sub
   .venv/bin/python -m src.evaluate --part eval
   ```
   Вторая команда считает только вариант из `results/zs_choice.json`, который записала первая.

Тесты: `.venv/bin/python -m pytest -q`.

## Структура

- `src/config.py` - пути и константы.
- `src/data.py` - таблица кадров из архива разметки, части train_sub / eval / train, чтение кадров из zip.
- `src/queries.py` - запросы из сочетаний атрибутов, галерея запроса, порог.
- `src/prompts.py` - тексты запросов по шаблонам.
- `src/embed.py` - эмбеддинги CLIP для кадров (crop и pad) и текстов.
- `src/metrics.py` - P@k, R-precision, AP и их ожидание для случайной выдачи.
- `src/evaluate.py` - скоринг, метрики по запросам, разбивки, выбор варианта на train_sub.
- `notebooks/01_eda.ipynb` - разметка, undefined, сочетания атрибутов, выбор порога.
- `notebooks/02_colab_embeddings.ipynb` - эмбеддинги кадров в Colab.
- `notebooks/03_zero_shot.ipynb` - сравнение вариантов, метрики на eval, удачные и провальные запросы.
- `tests/` - тесты метрик, запросов и оценки на игрушечных примерах.
- `results/` - таблицы и графики, на которые ссылается README.
